# V1导演蓝图人物重构

本Skill与Default H3 Prompt Writing一起使用，只处理用户有权二创的V1素材。

## 重制引擎

Remake Engine现在由Skill自动选择并锁定。没有Special Skill或选择其他任何Special Skill时，Studio显示**Create H3 Remake**并调用普通H3重构流程；选择本Skill时自动显示**LoRA Preserve V1**，这是唯一会加载`MiniMax-H3-Character-Swap-LoRA`、`LabsH3PrepareVideo`和`H3RelayWindowedEdit`的路径。旧Project曾保存的Creative／Directed手动选项会按当前Skill自动迁移，不再覆盖路由。

Director Design必须先建立完整的V1角色、Shot、说话者／听众、场景与时间账本，不得输出ComfyUI节点或Relay checkpoint。Studio在运行时抽取当前V1 Shot的精确24fps片段。LoRA每次只替换一个目标演员，因此多人Shot会依次处理：先处理受保护的听众／非说话者，最后处理当前说话者；前一轮输出成为后一轮输入。

V1在Design里仍是`analysis_only`，也不会进入普通H3参考槽。唯一例外是Studio运行时把当前Shot临时送进专用Relay source input，避免旧参考编译器与P演员池互相竞争，同时保留V1的表演、场景、构图、运镜、时间和原声。

## 素材职责

- `@V1`：在Design中只用于分析；运行时由Studio建立逐Shot 24fps Relay底片，保留剧情、场景、动作、运镜、剪辑与原声时间；
- `@P1`：唯一必需的替换身份，可以有意复用于V1检测到的全部角色；
- `@P2`至`@P9`：在V1主要角色绑定表中按需选择的可选替换身份；
- 其他已加载P图：只在V1存在对应第五位或后续主要角色时按需启用。

Qwen先为源片人物建立R1、R2、R3等内部稳定ID。分析完成后，Studio暂停，把每一次人物出场拆成独立的正方形脸孔卡片，严格按V1时间排序并以每行6张显示；每张卡片只显示自己的时间区间并使用该时间点的V1面板裁切，内部R编号不显示。同一人物的所有时间卡片第一次建立时沿用同一建议P图，但建立后不锁定、不联动。当检测角色多过已加载P图时，Studio会循环复用现有演员池；如果只有P1，所有卡片默认使用P1。用户可把每张时间卡片独立指定为任意已加载P图、让不同时间点复用同一P图，或选择`V1 DEFAULT · Keep source actor`。保存后的“R角色＋场景”账本是对应Shot、发声轮次与Segment的唯一人物映射，不得退回按P1、P2顺序猜测。即使后段改用另一P图，源角色的剧情职责和发声功能仍然延续。选择V1 Default时，Studio把该时间卡片的裁切物化成新的受控P身份参考。其他分析缩略图仍只供UI识别，绝不能送进H3。

如果另外加载了P5等人物图，把它们视为可选演员容量。只有V1确实存在并分配了对应主要角色时，Studio才自动建立该P人物的分时`existing_media_uses`；没有角色职责便保持未使用。Shot需要尚未加载的P人物时，必须明确提示缺少哪张Picture，禁止用其他脸替代或临时编造人物。

## Design前完整分析V1

读取V1完整时长、按时间排列的画面、语义分析、场景变化、运镜、Beat／VAD及声音证据。每个检测到的场景至少抽取一帧；长片最多拆成三张清晰的带标签故事板，而不是把所有场景缩进一张看不清的图。Design开始前，把这些故事板像素直接送给Design设置中的LM Studio视觉模型（当前为`qwen3.8-uncensored-nvfp4-mtp`及所设`/v1`地址），强制返回通过Schema检验的Qwen导演账本：每个检测区间必须有一行，并包含稳定角色ID、地点账本、可见事件、动作交接、镜头语法与连续性限制。Design必须等待账本完成并逐行使用。另以独立Contact Sheet显示全部已加载P演员，避免附件限制丢掉后段V1或P人物。建立：

1. 场景与Shot边界；
2. 主要角色进场、离场与角色交接；
3. 动作起因、回应、结果及下一状态；
4. 发声者与听众的时间；
5. 景别、角度、运镜目的与剪辑节奏；
6. 代表性的建筑、道具、天气、时段、灯光及群众功能；
7. 原声停顿、重叠、音乐、环境声与Foley时间。

Qwen账本还必须为每位主要角色的每个出场区间分别提供early／late／midpoint面板、脸部可见度与近似正方形脸部裁切范围，并另外指定最清晰的代表裁切。裁切坐标必须以所选单独面板为基准，禁止使用整张Contact Sheet坐标。所有R角色完成绑定后才允许继续Design；P图可以重复使用。BPM、VAD、Whisper、confidence、文件名与时间戳只作内部分析，不得进入画面或语音。

Contact Sheet中的画面像素与通过Schema检验的Qwen导演账本，高于含糊的BLIP描述或转录片段。BLIP只保留为低层识别／缩略图辅助，不再负责导演级剧情理解；Qwen视觉请求失败时禁止静默退回纯文字猜测。只有连续画面明确出现不同建筑空间，才允许判断场景转移；制服、白外套或人物服装本身不能证明地点变成实验室、办公室、医院等新场景。证据不足时延续最后一个已确认地点，只描述画面中真正可见的动作。

## V1分析账本与专用Relay底片

V1在Design JSON中必须设置为`analysis_only`，绝不能占用普通H3 Video参考槽。只允许Studio在运行时把当前Shot物化为专用Relay底片；Design不得把这段片放进`existing_media_uses`或一般参考槽。

以V1作为画面与表演底片，只替换已经映射的人物身份：

- 保留事件次序、人物交接、动作因果与场景功能；
- 保留实际运镜，例如揭示、跟拍、反应、推进、横移或转场；
- 保留V1的地点类型、建筑拓扑、主要背景物件、物件邻接关系、空间深度、色彩、实际光源方向、镜头感、构图、视线方向与人物阻挡关系；
- H3为合成新演员可以重新绘制像素，但不得主动重建或替换V1背景、群众、道具、天气与灯光；
- 只有明确选择`V1 DEFAULT · Keep source actor`的角色可以通过其物化P裁切保留原脸，其余V1原演员的脸、发型、身体与服装不得残留。

P图只替换V1中已映射的演员，不能触发重新发明场景或世界。

## 时间线与Segment

使用V1精确可播放时长，从0.000秒连续覆盖到真实终点，禁止循环、拉伸、四舍五入、删短或延长。

按照真实场景或事件边界建立连续Shot。LoRA Preserve V1逐Shot隔离，并由Relay在Shot内部使用自适应窗口与生成历史；不得跨越Hard Cut。后续Segment继承上一段的物理状态，不得重播前段事件。

某段只有一两位主要角色时，只为该时间段启用并显示真正需要的P人物。禁止因为多张P图存在于人物字典，就把整个演员池同时送进H3。其他人物只能是匿名非发声群众，不能继承P身份。

每个Shot的动作文字只能写该Shot实际可见的P身份，禁止在每个Shot重复整套P演员字典；Studio会依照这些局部人物标记决定每个Segment真正上传哪些图片，并自动补上对应的分时`existing_media_uses`。

## 原声

每个H3 Segment生成前，Studio先切出V1完全相同时间段的原声，并把它作为该Segment唯一的独立音频表演时钟。对应的P角色必须跟随原声的音素、开合嘴、下颚、呼吸、停顿与重叠时机；画面中的听众保持非发声嘴形。音频绝不能带入V1原演员的视觉身份。最终合成再恢复V1未经修改的内嵌原声，并以它作为唯一Master Audio。`text_layers`保持为空；禁止转录、翻译、改写、重复或新增对白、旁白、歌词及替代音乐。

按照分析出的说话轮次规划嘴形：当前发声角色才活动嘴唇，听众与群众保持自然非发声嘴形。

## 图片预算

不生成新的P人物身份、替代演员、姿势图、反应脸、环境母版或逐Shot图片。P5及后续人物只有在用户已经加载且V1确实存在对应主要角色时才可按需启用。H3从专用V1 Relay底片保留环境，`media_requests`必须为空。

## 输出检查

- V1精确时长与连续Shot覆盖；
- 每个Qwen R角色都有一个用户确认的绑定并写入`source_role_bindings`；允许重复使用同一P图；
- V1在Design中只作为`analysis_only`；LoRA模式的Shot局部Relay输入是唯一运行时例外；
- 已加载且被分配到真实V1主要角色的P图，是按各自出场Shot分时启用的H3人物身份锚点及唯一主演；
- 保留V1事件次序、因果、表演、场景、运镜与剪辑节奏，只替换映射人物身份；
- 没有未选择的V1原演员、意外复制人物、新发声角色、无请求生成参考图或Text Layer；
- 最终声音为V1原声；
- 结尾完成原事件，不开始新动作。
