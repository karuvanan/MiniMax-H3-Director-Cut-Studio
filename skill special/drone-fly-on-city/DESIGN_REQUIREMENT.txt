使用本 Requirement 前，必须在 Media Pool 中真实加载 `@P1` 与 `@P2`；缺少任何一个即停止并要求补齐，不生成视频提示词。`@P1` 是必填的场景母版与唯一视觉依据。视频开场必须匹配 `@P1`，并严格保持其中的地点、建筑、物件、布局、天气、时间、光暗方向与强度、色调、颜色、调色、曝光、对比度、氛围、镜头质感及特效。

`@P2` 只能是红色航线控制图：只读取红线的起点、转弯、曲线与终点，并转换成抽象文字航点。绝不可将 `@P2` 用作 H3、Z-Image、首帧、尾帧、构图、风格或场景参考；也绝不可把其中的红线、箭头、标注、颜色、文字、图形或其他视觉元素加入视频。

输出 Design JSON 时，`existing_media_uses` 必须登记已加载的 `P1` 与 `P2`：`P1` 的 `usage` 固定为 `h3_reference`，作为场景母版；`P2` 的 `usage` 固定为 `route_control_analysis_only`，并明确写明它只用于航点解析、绝不可作为视觉输入。此登记只用于通过 Media Pool 预检，不得将 `P2` 升级为视觉参考。

需要补充途中或结尾参考画面时，可由 Skill 创建未命名的 Z-Image 媒体请求；所有补图只能视觉参照 `@P1`，仅允许按航点改变机位、取景或目标视角，其余场景属性必须与 `@P1` 一模一样。补图实际生成并加载后，才可使用其真实编号；不得预先引用未加载的编号。

制作一段连续的 MiniMax H3 航拍视频：无人机必须严格依照从 `@P2` 红线提取的文字航点顺序飞行，逐一匹配红线的起点、每个关键转弯、曲线方向与终点；航点轨迹不得简化、拉直、跳过弯道或偏离路线。无人机在沿航线平移的同时，完成一次受控的 360 度环绕拍摄或偏航（yaw）旋转。最终视频的视觉参考只能使用 `@P1` 与已加载的无覆盖层补图，绝不包含 `@P2`。强制彻底隐藏所有红色航线、红色 waypoint、路径线、箭头、标记、HUD、UI、注释、涂鸦和控制图元素。最终 H3 Prompt 必须附加负面提示词：`red waypoint, red route line, route path overlay, flight path line, map line, red arrow, waypoint marker, navigation marker, HUD, UI overlay, annotation, graphic overlay, red scribble, red stroke, visible control path, visible route guide`。飞行须平滑、稳定水平线、具有自然航拍视差与符合物理规律的加减速，并避免碰撞；禁止瞬移、随机旋转、镜头抖动、穿模、红色标记残留或场景突变。
