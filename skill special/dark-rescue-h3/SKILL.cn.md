# 暗黑救援 H3 导演

本 Special Skill 与绑定的 Default H3 Prompt Writing Skill 一起使用。本 Skill 负责故事创作、地点适配、第一人称救援调度、已验证光影效果和可编辑 Timeline 设计；Default Skill 负责最终 MiniMax H3 Ref2VA 结构及每次请求的动态参考编号。

## 理解一句简单需求

用户只写「帮我创作一个废弃的华尔街大楼45秒视频，按照Skill给我合适的对白和旁白」时，直接扩写，不询问可以安全推断的细节。

优先保留用户指定的时长、地点、职业、语言、画幅、人物、参考素材、结局和安全要求。未指定时采用：

- 精确45.00秒，所有时间落在0.5秒网格；
- 电影级写实真人实拍；
- 所有台词使用普通话；
- 一名第一人称救援者与一名成年受困者，默认只有这两种可辨识人声；
- 真实地点只作为虚构受损或停用空间的灵感，不声称真实学校、街道、地标或大楼已经废弃或发生灾难；
- 非血腥危险与救援，结尾由压迫黑暗过渡到一个有真实来源的微弱外部光线。

职业必须由灾害决定：上锁废楼、暗巷、失踪者或搜索环境使用警察；存在浓烟、火警、爆裂喷淋、重大结构损坏或高层灾害时使用消防员。中途不能换职业。

每次重新创作片名、具体险情、障碍、路线变化、对白和旁白。五个已验证剧本只作为结构与视觉资料库，不逐句复制；不能每次自动重复「跟着我的光」「不要回头」或相同结尾金句。

## 保持可执行的说话角色

默认只使用两个稳定声线：

- `S1`：成年受困者，未指定时通常为女性；
- `S2`：第一人称救援者，未指定时通常为男性；克制的第一人称内心旁白也沿用S2声线。

对讲机默认只使用杂讯、提示音和不可辨识的调度声底，不自动增加第三名清晰说话者。只有用户明确要求、而且当前Studio schema支持时才加入第三个声线。

每句Dialogue与Voice-over都必须建立独立、带时间的 `text_layers`，并设置 `explicit_user_requested=true`。逐字台词不能写入 `subject_action`、`environment_response`、`continuity_state`、`optional_flourish`、图片提示词或可见招牌。现场对白用 `dialogue`；只有S2短促内心反思使用 `voice_over`；不自动生成Lyrics。

对白必须原创、短促、符合险境中的真人说话方式。默认45秒大约安排：S2到场或状态一句、S1提供位置或求救一句、S2给出实用安抚或行动指令一句、路线改变确认一句、结尾S1或S2一句，以及最多两段每段一至两句的S2旁白。

按自然普通话语速、呼吸和犹豫预留时间；不够时延长或重排所属Shot。禁止加速到不自然、提前说、重复、改字、漏字、换Speaker或切断最后一个字。

服从Design字幕开关。SUB OFF时不把对白转成 `on_screen_text`，也不让参考图片烧录字幕；SUB ON时只建立同步且可编辑的字幕Text Layers。只有用户明确要求可见结尾文字时才加入标语。

## 建立因果清楚的救援分镜

45秒默认使用九个连续5秒Shot，组合成三个原生15秒段；对白需要时可以调整边界，但必须完整覆盖0.00–45.00秒。

1. **0–5秒：外部钩子与到达。** 建立地点雨后外观、救援职业和一项证明有人在内的具体线索。
2. **5–10秒：跨越入口。** 打开、破除或穿过一个入口；关门后外部声音减弱，室内声场接管。
3. **10–15秒：第一个搜索线索。** 手电照出地点特有破坏与一个声音或物理线索；结尾保持单一清楚方向，不开始新复杂动作。
4. **15–20秒：障碍与深入路线。** 攀爬、弯腰或越过一个破损障碍，接触与后果必须可见。
5. **20–25秒：找到受困者。** 只出现一名受困者，先建立困住他的物体，不能同一瞬间完成发现、救出和撤离。
6. **25–30秒：控制性解困。** 最多移开两件阻挡物，建立手部接触，结尾让受困者恢复移动能力。
7. **30–35秒：路线改变。** 一个有物理原因的损坏堵住原出口，救援者选择替代路线。
8. **35–40秒：最后上升或出口前段。** 沿替代路线前进，打开最后一道门、舱口或破损出口。
9. **40–45秒：外部释放与Final Hold。** 建立开放空间、获救者稳定位置与呼应地点的远景；以结果收束，不再加入危险。

其他时长按相同因果顺序缩放Shot数量；禁止把九个段落硬塞进15秒。每5秒最多三个必须完成的物理动作、两个必要接触后果和两个可选装饰动作。

每个Shot必须包含：一个故事职责、一个主要镜头运动或固定镜头、只写核心动作的 `subject_action`、只写接触后果的 `environment_response`、记录手部/工具/受困者/路线/手电方向和未完成运动的 `continuity_state`、可省略的雾气/纸张/小火花/次要灯光，以及第一人称可见范围、表演和曝光规则。

15秒与30秒边界前留下一个清楚的物理状态。下一段继承后马上推进，禁止重复开门、攀爬、发现、牵手、坍塌或改道。上一段24帧只能作为视觉运动上下文，不能成为声音参考。

## 锁定第一人称连续性

镜头始终是救援者眼睛位置。只能合理看到湿污手套、手电筒、对讲机、头盔边缘、制服袖口、反光条、消防斧或一件符合职业的工具。禁止切到第三人称英雄镜头、看见救援者脸、镜头离体漂浮，或在一只手持工具时又出现不可能的双手配置。

全程记录并保持：人物数量与身份、职业装备与工具归属、受困者服装/湿污/行动能力/牵手状态、门与残骸状态、楼梯/水管/电线/积水与路线状态、手电开关与光束方向、房间地理/楼层/屏幕方向和已走距离。

堵住的路线持续堵住；搬开的柜子不能复位；破坏的锁不能恢复；水向低处流；坍塌后先扬尘再沉降；人物必须经过可见路线才能改变楼层。

## 只使用已验证的光影效果库

只能从以下封闭效果库选择。每个效果必须有已经建立的真实光源和叙事作用；不要每个Shot堆满所有效果，也不要新增超自然能量、怪物、不可解释光线或奇观。

1. **幽闭低调光：** 约80–90%画面处于深黑，但正在发生的手部、障碍、脸或路线必须可读。
2. **手电筒即武器：** 战术手电是稳定视觉窗口；光束内冷白刺眼，外部接近绝对黑；每次只揭示一个线索或动作。
3. **动态光影：** 手电、警车探照灯、实景招牌或警报灯随真实光源移动，在湿墙、金属门、玻璃和积水上滑动。
4. **体积光与体积散射：** 只有已建立雨雾、蒸汽、灰尘、烟或水汽时才显示光束。
5. **明暗对照与锐利终止线：** 使用硬边局部高光与大面积负空间，禁止平均补光。
6. **剪影与逆光：** 门口、破窗、月光、街灯或救援灯产生克制轮廓光；不能暗示怪物。
7. **故障霓虹或灯管闪烁：** 由进水或损坏线路造成，短促、不规则；关键动作与对白期间禁止持续高频频闪。
8. **机械动态阴影：** 只有已经出现的风扇或排气叶片才可切割、拉伸固定灯源的影子。
9. **紧急红色旋转警报灯：** 必须先建立警报或备用电路，周期性染红雾气与湿表面后回到黑暗。
10. **潮湿高镜面材质：** 雨水、冷凝、漏水、油膜和工业湿污形成局部高光；“有机潮湿”只表示材质质感，不能变成黏液、血肉或异形。
11. **IES工业灯管：** 一盏损坏实景灯可短暂照亮局部，其余空间继续保持黑暗。
12. **复古工业污垢：** 真实铁锈、剥落油漆、霉斑、湿纸、弯曲铁网、旧机械与损坏设施；保持写实、非超自然。

灯光变化必须保持曝光连续。光源必须先出现或被描述，之后才可熄灭、旋转或被遮挡。禁止用随机闪烁掩盖换脸、瞬移或连续性错误。

## 选择已验证地点模块

选择最接近的一种，再适配用户地点；不得宣称现实地点真实受损或废弃。

### 废弃学院／校舍

虚构哈佛风格、英美或其他旧学院可使用红砖、石拱门、讲堂、图书馆、实验室、旧楼梯和天台。已验证残骸包括浸湿书本、倒下书架、裂黑板、破玻璃器皿、金属柜、爆裂水管和故障灯管。真实校名不能进入灾难事实陈述。

### 曼谷耀华力路后巷

从雨夜市场入口进入狭窄服务巷、旧旅馆或店屋楼梯。使用合理泰文/中文招牌、红灯笼、小吃车、塑料凳、铁卷门、湿纸箱、排水管及远处嘟嘟车或摩托声；文化细节必须观察式而非刻板化。

### 吉隆坡茨厂街后巷

使用红灯笼、旧中文店招、收摊摊位、茶室或店屋楼上、木楼梯、卷门、湿报纸、水果筐、排水声和远处城市/警笛声。天台可呈现吉隆坡城市光，但不能发明不合理地标位置。

### 历史九龙密集室内

九龙城寨必须明确为虚构历史重现。使用极窄叠层走廊、密集电线、漏水管、锈门、木/铁楼梯、小房间、残余霓虹与层层天台；不能把历史地点描述成当代真实灾区。

### 受损高层办公室／华尔街风格大楼

使用受曼哈顿下城或指定金融区启发的虚构停用/受损办公楼。出现浓烟、警报、喷淋或重大结构损坏时选择消防员。已验证细节包括倒塌隔墙、外露金属龙骨、垂线、爆裂喷淋、积水、翻倒办公桌、破显示器、浸湿文件、弯曲楼梯扶手及迎风天台或破窗出口。结尾天际线只用于空间定位，不代表真实建筑灾难。

未列地点只能组合最接近的结构模块与合理当地材料、天气、文字系统和声音。没有剧情理由时，禁止把泰国灯笼、英国警装、中文店招或美国办公室残骸搬到错误地点。

## H3原生现场声音

从画面真实声源建立 `overall_soundscape` 与每个Shot的Native Audio Direction。声音由H3原生生成；禁止要求外部TTS替换、语音分离、FFmpeg混响、EQ、卷积或后期重混。

维持三层：持续存在的现场环境声、画面接触瞬间的Foley、只在指定时间出现的前景Dialogue或S2 Voice-over。

只使用画面支持的已验证声音：雨后滴水、湿地脚步、破窗风声、远雷或警笛、对讲机杂讯、损坏电流、霓虹/灯管滋滋声、铁门撞击、木楼梯吱呀、排水/管道轰鸣、蒸汽喷出、风扇机械声、警报脉冲、斧头/门锁接触、残骸掉落、呼吸及天台风声。

声学必须匹配空间：暗巷和楼梯间使用短促定向反射；小房间使用短而近的反射；大讲堂/办公室楼层使用较长但受控的衰减；天台与街外几乎没有房间尾音并减少低中频饱满感。关门后外部环境声变小且受阻；打开最终门时结束室内尾音并建立风声与城市距离。禁止让Echo重复台词。

对白必须像在画面距离真实同期收音，保留呼吸与低量环境渗入，不能像录音棚播音。环境效果清楚但低于逐字对白。禁止复制Audio/Video参考里的台词或声线，也不能把上一Segment生成音频带入下一段。

服从Studio音乐三态选择：

- `MUSIC AUTO`：低沉克制工业配乐，使用稀疏低频脉冲或金属质感；改道危机才升压，最终室外只加入极少温暖和声，不变成胜利凯歌。
- `MUSIC OFF`：`non_diegetic_music` 必须为 `N/A`，只依靠环境声、Foley和对白。
- `MUSIC TIMELINE`：不自动创造配乐或Music Cue，只服从用户建立的Timeline Music Cue。

音乐不能遮盖对白，除非用户明确要求Lyrics，否则不能有人声歌唱。

## 参考素材纪律

只有素材真实加载并选中时才使用其稳定Media Pool编号，而且只能引用用户实际写出的 `@P`、`@V` 或 `@A`。简单需求没有明确 `@ID` 时，Skill绝对不能自行发明 `@P1`、`@P2`、`@V1` 或 `@A1`。

先复用有效素材，再请求缺失素材。第一人称救援不应浪费图片建立看不见的救援者脸；优先保持受困者身份、地点、关键障碍或原生边界状态。每张生成参考图只能显示一个冻结瞬间、正确人物数量及真实剧情环境，禁止中性摄影棚背景或一张图描述连续动作。

地点、损坏、受困姿势和边界参考必须限制在需要的Shot。禁止前段校舍、暗巷、旅馆、茶室或办公室素材污染后段地点。Virtual Media Pool可容纳很多逻辑素材，但每个原生Segment仍必须遵守9 Picture／3 Video／3 Audio实体参考限制。

## 输出Studio Director Design JSON

返回一个覆盖完整精确时长、符合当前schema的Director Design JSON。Design阶段不能返回剧本Markdown或最终六段H3 Prompt；绑定Default Skill与Studio编译器会完成最终转换。

只使用现有schema字段。Shot按时间连续、不重叠、覆盖每一帧并落在0.5秒网格；只在真实结尾建立一个Final Hold。所有语音放入 `text_layers`；复用或生成素材放入 `existing_media_uses`／`media_requests`；声音和音乐写入支持的sound字段。

Constraints必须明确保护第一人称镜头、人物身份、制服、工具、受困者数量、路线地理、湿度/损坏状态、真实光源、逐字台词、非血腥写实与核心动作优先级。任何可选气氛都必须先于核心动作被删除，不能造成核心动作延迟或重播。

## 交付前检查

- 地点已负责任地虚构化，并使用正确文化/建筑模块；
- 职业符合灾害且全程不变；
- 镜头从未离开第一人称，也没有不可能的身体配置；
- 除非用户明确要求，否则只有一名受困者；
- 默认只有S1/S2说话，每句逐字台词只在可编辑 `text_layers` 出现一次；
- 每5秒动作预算可执行；
- 障碍、工具、门、牵手、路线和光源状态连续；
- 所有视觉效果来自已验证效果库并具有物理来源；
- 每个Segment不重播上一个边界动作或声音；
- 参考编号来自真实已加载素材或合法缺失素材请求，绝不指向空栏；
- 字幕与音乐服从Design选择；
- 不出现血腥、尸体、伤口特写、酷刑、怪物、鬼魂、超自然、无意义爆炸、畸形身体、多余肢体、过度频闪、随机持续抖动、动画、卡通、水印或乱码文字；
- Final Hold只保持救援完成状态，不加入新动作。
