# MiniMax H3 Director Cut Studio v0.3.1 Acceptance Checklist

This checklist is the release contract for the budget-aware long-form production upgrade. A checked item must be backed by an automated regression or a documented manual production test. The final release may be named `v0.3.1` only after every **Required for v0.3.1** item passes.

## Release invariants

- [x] Existing `.h3director.json` projects remain loadable without modifying, moving or deleting their original files.
- [x] Opening a legacy project creates or adopts a fixed Project Workspace non-destructively and records the original project path in the Workspace manifest.
- [x] Saved P/V/A logical IDs, Timeline clips, text layers, Shot cues, render manifests and generated output remain compatible.
- [x] One failed Shot, missing Take or interrupted render cannot invalidate an approved Shot or the complete project.
- [x] All eight Standard Pipeline Release Gates remain green.
- [x] Project-format and application-version migrations are explicit, tested and reversible by retaining the old file.

## Alpha.1 — fixed Workspace, quality tiers and budget visibility

### One project, one fixed working directory

- [x] A new project receives one stable Workspace root; repeated Design, Preview, Accept and Final operations never create another top-level project folder.
- [x] The Workspace contains `project`, `design/revisions`, `media/imported`, `media/generated_references`, `media/audio`, `segments`, `shots`, `renders/preview`, `renders/final`, `proxies`, `cache` and `logs`.
- [x] Every Design revision is stored inside the same Workspace as `design/revisions/R####`.
- [x] Workspace 根目录最多保留一份 `generated_preview.mp4` 和一份 `generated_output.mp4`; `renders` 只保留轻量 manifest 资料。
- [x] The canonical autosaved project is stored under `project/director_project.h3director.json`.
- [x] `project_manifest.json` records a stable Workspace ID, display name, created/updated time, original legacy project path and layout version.
- [x] Reopening a new-format project restores the same Workspace even when an obsolete absolute Workspace path is saved.
- [x] Cross-computer restoration resolves media beside the opened project before considering old absolute paths.

### Segment Take and Shot approval state

- [x] Every Render Segment stores at most one Motion Preview and one Approved Final; Shot state stores references and source ranges instead of MP4 aliases.
- [x] Workspace layout 1 Shot Takes migrate to layout 2 only after canonical Segment output hash verification.
- [x] Completed `.director_cache/generated_outputs` runs are removed only after Master, Segment files and project snapshot are durable.

- [x] Every Shot cue has a persistent Shot state keyed by its stable `cue_id`.
- [x] Shot state records render status, render profile, seed, Take count, latest Take, approved Take and output path.
- [x] A 0.2MP preview creates a Preview Take without silently approving it.
- [x] Accept preserves the preview seed and promotes the resulting 1.0MP Take to approved.
- [x] Reject advances only the affected seed/Take and does not delete approved output.
- [x] Approved Shot state survives Save/Open; Alpha.1 does not lock Timeline editing (explicit locked-range controls are an Alpha.2 item).

### Three quality tiers

- [x] `Storyboard` is a no-H3 planning state suitable for immediate Timeline playback from references/placeholders and authored audio.
- [x] `Motion Preview` uses 0.2MP, disables RTX upscaling and does not overwrite Final output.
- [x] `Approved Final` uses 1.0MP with the accepted preview seed and optional RTX upscaling.
- [x] The selected tier is visible before Queue and stored in the project.
- [x] Preview and production Smart Render caches remain isolated.

### Resource estimate and protection

- [x] Before generation, Studio estimates Shot/Segment count, new versus reusable duration, GPU minutes and additional disk space; Alpha.2 derives reusable time from non-dirty cached Segment cores.
- [x] Estimation uses a persistent local calibration profile and clearly labels uncalibrated estimates.
- [x] Finished jobs update the calibration with observed wall time and output bytes.
- [x] Generation is blocked when estimated output would violate the configured free-disk reserve.
- [x] The estimate distinguishes Storyboard, 0.2MP Preview and 1.0MP Final.
- [x] Resource estimates never change P/V/A mapping, Shot fingerprints or seeds.
